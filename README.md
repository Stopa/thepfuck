# thepfuck

[thefuck](https://github.com/nvbn/thefuck) is great. I use it all the time 
and it's one of the first tools I install on a fresh machine. But it's 2026 
and everything has to be AI. So why not use the LLM that comes bundled 
with all the macs([apfel](https://github.com/Arthur-Ficial/apfel)) to fix your 
typos instead?

Besides, `thefuck` can only get you so far. Yes, it will save your life if 
your mistake aligns to one of it's patterns, but it can easily miss  pretty 
simple typos:

```bash
❯ docker compos version
docker: unknown command: docker compos

Run 'docker --help' for more information
❯ fuck
docker compos version [enter/↑/↓/ctrl+c]
```

Whereas this tool uses advanced artificial intelligence to get it right

```bash
❯ pfuck
docker compose version [enter/ctrl+c]
```

## Requirements

- Apple Silicon and a macOS version supported by apfel
- Apple Intelligence enabled and available
- `apfel` installed and on `PATH`
- zsh or Bash

Install apfel with Homebrew:

```bash
brew install apfel
```

## Install

From this checkout, build and install `thepfuck` into `~/.local/bin`:

```bash
make install
```

For zsh, persist the binary path and shell function, then reload the shell:

```bash
printf '%s\n' 'export PATH="$HOME/.local/bin:$PATH"' 'eval "$(thepfuck --alias)"' >> ~/.zshrc
source ~/.zshrc
```

For Bash, persist the binary path and shell function, then reload the shell:

```bash
printf '%s\n' 'export PATH="$HOME/.local/bin:$PATH"' 'eval "$(thepfuck --alias --shell bash)"' >> ~/.bashrc
source ~/.bashrc
```

## Use it

Run a command that fails:

```bash
git stats
```

Then invoke the fixer:

```bash
fuck
```

`thepfuck` shows a candidate such as `git status [enter/ctrl+c]`. Press Enter
to execute it in the current shell, or press Ctrl-C to cancel.

To choose another function name, generate that function in your shell config:

```bash
eval "$(thepfuck --alias oops)"
```

Then invoke it after a failure:

```bash
oops
```

To execute the suggestion without confirmation, explicitly opt in:

```bash
fuck --yes
```

`--yes` evaluates model-generated shell code without review. It is intentionally
not the default.

To diagnose and retry a specific command outside shell history, invoke the
executable directly. Press Enter to run its suggested correction:

```bash
thepfuck --command "git stats"
```

Direct mode runs the correction in a child shell. Use the generated `fuck`
function when changes such as `cd` or exported variables must persist in the
current interactive shell.

Use a shorter capture deadline for commands that are expensive to retry:

```bash
fuck --timeout 1
```

See every option:

```bash
thepfuck --help
```

## How it works

The generated shell function reads recent history and skips its own invocation.
The native executable then:

1. captures the interactive shell's aliases, expands a leading alias, and
   re-runs the expanded command in a child login shell with combined stdout and
   stderr and a bounded timeout;
2. sends the command and captured output to `apfel -q --code` as untrusted JSON
   data;
3. validates the candidate and displays it on the terminal;
4. writes only an accepted command to stdout;
5. lets the shell function add it to history and evaluate it in the current
   shell.

This stdout/stderr split is deliberate: diagnostics and prompts can never be
mistaken for a command to execute.

## Important limitations

- The failed command is run a second time to capture its error, matching
  thefuck's default mode. Commands with side effects can therefore repeat those
  effects. A future terminal-logger mode could avoid the re-run.
- Corrections are generated by a small on-device model and can be wrong. Review
  the command before accepting it, especially when it modifies or deletes data.
- A leading shell alias is expanded before error capture and before the command
  is sent to apfel. Functions, nested aliases, and other interactive-only shell
  state are not expanded, so commands that depend on them may still behave
  differently when re-run.
- Direct `--command` corrections run in a child shell, so directory and
  environment changes do not persist after the command exits.
- This release supports zsh and Bash. Fish is rejected with a clear error rather
  than claiming incomplete compatibility.
- apfel's model availability and safety guardrails apply. If apfel refuses or is
  unavailable, no command is emitted or executed.
